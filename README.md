# 《一朝天子》（网页游戏 Prototype 0.2）

以王朝为包装的轻量随机抽牌策略网页游戏原型。

> **0.2 核心玩法重构目标**：告别单纯的“四维数值加减按钮”，实现**「局势 × 随机手牌 × 不同处理方式 → 不同后遗症 → 新的未来局面」**的真正因果碰撞体验。

---

## 一、0.2 核心重构与系统机制

1. **目标自动锁定 (Auto-Targeting)**：
   - 当手牌面对场上局势存在**唯一明显合法目标**时，系统自动锁定该目标并高亮显示（如手握【调兵北上】且场上只有【北境犯边】，自动锁定无需多余点击）。
   - 存在多个目标时提示玩家选择；无对应局势时执行通用政令或明确提示。
2. **局势三阶段压力与放任离散后果**：
   - 场上最多 3 个局势（通常 1～2 个）。
   - 负面局势采用三阶段压力印记：
     - `●○○` **征兆**：隐患初起；
     - `●●○` **恶化**：若放任不理，季末触发一次离散伤害与史册失守记录；
     - `●●●` **危急**：临界爆发，再放任将升级为重大危机（如【边境战争】、【大规模民变】、【宫廷政争】）。
3. **Reaction Matrix 数据驱动交互矩阵**：
   - 每个局势具备多种不同维度的解法，每种解法具备不同评级（★极有效、▲有效、△勉强、✕反噬）与完全不同的代价及后遗症。
4. **后遗状态 (Residues，因果的种子)**：
   - 场上最多 3 个后遗状态，持续 2～4 季。由明确语义行为产生（如开仓赈济导致【仓储空虚】、强征民夫导致【徭役沉重】、兴修水利成功留下【河防稳固】、依赖地方豪绅引发【豪族声望】）。
5. **真实实体牌库 (Deck System)**：
   - 24 张实体卡牌，抽牌堆 (Draw Pile) 与弃牌堆 (Discard Pile) 循环运转。手牌保证不出现同名牌重复，且具备智能抽牌保底机制。
6. **年度定策 (Annual Strategy)**：
   - 每年第 4 季末触发一次「朝议定策」三选一（重商、尚武、轻徭薄赋、巡按天下、盟誓诸部、雷霆手段），最多同时生效 3 项国策。
7. **出牌前预测与因果史册**：
   - 选牌即显示预期后果与后遗状态预告。
   - 史册按“原因 → 圣意决断 → 产生后果与后遗症”记录因果链。
8. **Telemetry 0.2 深度遥测**：
   - 准确记录出牌前手牌 `hand_before_play`、自动索敌 `auto_targeted`、交互评级与 `Meaningful Choices`（手牌中有效解法的多样性指标）。

## 二、项目文件结构

```
.
├── index.html                 # 游戏主页面 (16:9 御案奏折布局，含定策弹窗与印记)
├── style.css                  # 静雅古朴御案水墨样式表
├── server.js                  # 零依赖本地轻量静态服务器
├── package.json               # ES 模块配置
├── src/
│   ├── game.js                # GameState 游戏状态机与季度全流程编排
│   ├── data/
│   │   ├── balance.js         # 平衡数值、三阶段定义、常量配置
│   │   ├── cards.js           # 24 张卡牌实体定义与行为人格
│   │   ├── situations.js      # 12 种天下局势与危机升级链配置
│   │   ├── residues.js        # 12 种后遗状态定义与持续时间
│   │   ├── policies.js        # 6 种年度定策定义
│   │   └── interactionRules.js# 核心 Reaction Matrix 规则矩阵
│   ├── engine/
│   │   ├── prng.js            # Mulberry32 可复现伪随机数生成器
│   │   ├── deckManager.js     # 真实实体牌库 (Draw/Discard/Hand/Kept)
│   │   ├── situationManager.js# 局势三阶段推进、放任恶化与合并
│   │   ├── residueManager.js  # 后遗状态管理 (最多3个、持续倒计时)
│   │   ├── policyManager.js   # 年度定策 3 选 1 管理
│   │   ├── stateManager.js    # 四项宏观健康度与失败检测
│   │   ├── interactionResolver.js # 自动索敌、评级计算与后果结算
│   │   ├── historyManager.js  # 因果链史册编年史记录
│   │   ├── telemetry.js       # Telemetry 0.2 日志收集与 JSON 导出
│   │   └── saveManager.js     # LocalStorage 自动存档与读档
│   └── ui/
│       ├── renderer.js        # 局势印记、卡牌人格、快速留牌与盖印渲染
│       ├── debugPanel.js      # Debug 控制台 (含4大预设场景与矩阵透视)
│       └── modal.js           # 年度定策弹窗、终局弹窗与史册抽屉
└── test/
    ├── simulate.js            # 核心自动化全量回归测试 (42项断言全PASS)
    └── batch_test.js          # 20 局多种子无干预策略压力测试
```

## 三、快速开始与测试

### 本地启动
```bash
node server.js
```
浏览器访问：`http://localhost:3000`

### 运行自动化回归验证
```bash
node test/simulate.js
node test/batch_test.js
```

### 四大 Debug 预设测试场景（可在 DEBUG 面板一键点击载入）
1. **Test A: 黄河水患**：场上黄河水患·恶化 (2阶)，手牌配备开仓、水利、民夫等，测试同一问题至少有 3 种完全不同代价解法。
2. **Test B: 北境危机**：场上北境犯边·危急 (3阶)，手牌配备武力、外交、互市、筹饷等，测试不同路线的不同后遗后果。
3. **Test C: 双重危机**：场上同时存在水患与北境犯边，测试在有限手牌下一轮只能解决一件时的真正取舍。
4. **Test D: 盛世建设**：场上出现江南丰收与海贸兴起，测试无危机时的投资与发展动机。
